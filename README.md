# Local Daily Checkin

Windows 本机的 **B站 + 小黑盒每日任务适配器**，由 Codex 每晚20:00调度，执行后生成一份合并日报。

程序、账号凭据与签名都留在使用者自己的电脑。默认不创建 Windows 计划任务，不把账号任务放到 GitHub Actions，也不接第三方签名或代挂服务。

**交给AI部署时，从 [AGENTS.md](AGENTS.md) 和 [AI部署约定](docs/ai-deployment.md) 开始。** 后者逐项写明外部依赖、官方来源、命令顺序及验收条件；[小黑盒资源清单](docs/heybox-resources.md) 写明资源格式、谁能提供和哪些获取环节尚未解决。小黑盒缺资源时应关闭该模块，不能把“双平台已部署”作为交付结果。所谓签名资源不是个人证书或私钥。

> **版本状态：0.1.1 源码版。** 原本机流程有真实任务完成证据；此通用发布版验证的是离线逻辑、报告、语法和发布边界。它尚未在另一位用户的电脑上完成端到端验收。尤其小黑盒缺少通用的签名初始化资源获取方法，**默认关闭，不能承诺新电脑一键跑通**。详见[小黑盒准备条件](docs/heybox.md)。

## 功能

| 模块 | 允许的每日任务 | 防重复与报告 |
| --- | --- | --- |
| B站 | 登录、观看、分享、视频投币 | 当天累计最多5枚，包含手动/自动已计入部分；Lv6停止升级投币；保留余额检查 |
| 小黑盒 | 签到，帖子/游戏详情/游戏评价三项模拟分享 | 先检查当天状态，已完成跳过，每阶段一次，无外发社交消息 |
| 合并日报 | 各项结果、当天任务经验、等级、剩余经验、预计天数、余额 | B站单列登录奖励硬币和投币去向；小黑盒单列签到H币奖励与连续天数 |

不执行点赞、关注取关、评论、弹幕、抽奖、漫画、大会员、充电、领券或付费操作。小黑盒的分享是**模拟分享完成事件上报**，不是给微信联系人发消息；平台是否计入奖励须以实际当天任务状态为准。

## 环境和目录

- B站：Windows、Windows PowerShell 5.1（启动）和 PowerShell 7（安全汇总）；官方自包含发行包无需另装 .NET。
- 小黑盒：Windows x64、Python 3.12、JDK17、Maven、Git，以及本人兼容App的资源；首次导入另需官方 Android Platform-Tools 和本人手机授权。
- 自动调度：已登录的本机 Codex 桌面端。执行时电脑开机联网、Windows用户保持登录、Codex保持运行；不依赖浏览器或手机一直连接。
- 当前代码默认北京时间 UTC+08 与20:00。不要只改配置中的时区文字来假装支持另一时区。

源码与私人数据分开：

```text
Git checkout/                         # 只放可公开源码
  scripts/                           # 安装、统一入口、日报和检查
  src/bilibili/                      # BiliBiliToolPro适配脚本
  src/heybox/                        # 本地签名/每日任务适配胶水
  config.example.json
  config.local.json                  # 本机配置，Git忽略

%LOCALAPPDATA%/LocalDailyCheckin/      # checkout之外，绝不推送
  bilibili/                          # 程序、凭据、日志
  heybox/                            # 私有运行资源、会话、日志
  reports/                           # 合并JSON及Markdown
```

自定义 `stateRoot` 可以用独立的D盘目录，但禁止放进本仓库。安装器不读取作者的现有安装、不修改系统代理，也不会迁移其他账号的数据。

## 首次部署

下面命令在仓库根目录、普通用户 PowerShell 中执行。若系统要求确认执行策略或手机授权，由使用者本人处理；不要通过关闭系统安全功能绕过。

### 1. 准备本机配置

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Setup.ps1
```

创建 `config.local.json`，已存在则拒绝覆盖；默认只启用B站。**这一步不访问账号、不安装程序、不创建调度。** 自定义路径后，下面各模块的 `-StateRoot` 须与配置的子目录一致。

### 2. 安装B站稳定版并扫码

```powershell
.\scripts\Install-Bilibili.ps1
.\src\bilibili\Launch.ps1 -StateRoot "$env:LOCALAPPDATA\LocalDailyCheckin\bilibili" -Mode Login
```

安装器从官方发行渠道取得固定稳定版，按可用发布方校验值核对。使用者通过手机哔哩哔哩App扫码确认，无需手动提取Cookie。官方完整来源、升级/备份和运行选项见[详细说明](docs/bilibili.md)。

### 3. 小黑盒为可选模块

**没有本人兼容签名资源时跳过本步骤，保持 `heybox.enabled=false`。** 手机USB授权只解决会话导入，不能自动补齐App运行时的shader初始化缓存。

具备资源后按[小黑盒文档](docs/heybox.md)安装、导入本人手机会话，确认预检通过，再在本机配置启用模块。公开包不包含App、原生库、初始化缓存、公钥材料或任何人的账号数据。上游未明确授予整体开源许可的原生桥源码也不再分发；不要把它当成本项目已授权的GPL源码。

### 4. 本机运行和查看结果

```powershell
# 立即处理今天；已完成的任务仍会跳过
.\scripts\Run-Daily.ps1

# 定时模式：20:00前跳过，不补旧日
.\scripts\Run-Daily.ps1 -Scheduled

# 只读已经存在的当日日报，不执行平台动作
.\scripts\Run-Daily.ps1 -ReportOnly
```

执行已开启的模块，结果写在外部 `stateRoot/reports/Combined-YYYYMMDD.json` 和 `.md`。只有真实业务完成/奖励记录可以报成功；退出码0不等于各任务成功。没有当日资料就写未确认，不额外请求接口补齐报表。

### 5. 让Codex创建每天20:00任务

```powershell
.\scripts\New-CodexPrompt.ps1
```

把生成的本机专用文字发给你自己的Codex，让它创建**一个**每天20:00的本地定时任务并核对启用状态。生成器只显示准确路径和指令，不直接编辑Codex内部数据库或自动化配置，也不会替你创建任务。

不要同时保留“B站单独任务”“小黑盒单独任务”和“合并任务”。本项目自带防重复检查，但一个调度更容易管理。[Codex官方定时任务说明](https://learn.chatgpt.com/docs/automations)。

## 每日规则

- 开始前看各模块暂停文件；存在则不联网，不自动删除。一个模块暂停不影响另一个独立检查。
- 当日完整完成就本地跳过；需要执行时保留平台当天进度检查。B站总目标是当天累计5枚，不是每次启动加5枚。
- B站保留余额0，不设累计消费预算；不足时减少/跳过，不充值。Lv6停止升级投币。
- 运行期间不要同时手动投币或另开其他投币工具。原生差额检查不能给所有客户端提供跨平台原子额度锁。
- 本地互斥防止并行；已经尝试但结果不明不自动重发。重复唤醒不是重做理由。
- 迟到触发只处理执行当天；新一天20:00前的旧触发跳过，不补历史日期、不补投。
- 遇登录失效、验证码、风控、接口拒绝或未确认即停止受影响操作并保留暂停，先处理原因。不会反复请求或修改代理来撞成功。
- 升级天数是估算：B站考虑硬币余额及以后每日登录所得1枚；小黑盒按当日任务经验和后续每天均完成估算，不承诺日期。

## 日报样式

每个平台各用一张四行表格，结果区分本次成功、今天已完成跳过、失败/未确认和暂停未执行。B站投币行同时写当天累计与本次新增；表后列经验、等级、升级差额/估算、余额、奖励与记录时间。

投币对象只简写：`UP主名｜视频简写｜1枚`。平台明细可能含手动投币，不把无法区分的来源冒称为本工具操作。

分享/登录任务的重复成功提示不能反复计经验。不同平台的经验与货币分别显示，不把它们加成一个总数。

GitHub Actions **仅运行离线检查**，没有定时签到workflow，不需要设置账号Secrets，也不下载/安装账户运行环境或运行账户任务。测试会校验安装器的拒绝路径，但不会进入真实安装。完整验证范围见[验证说明](docs/validation.md)，贡献方式见[CONTRIBUTING](CONTRIBUTING.md)，推送和发行步骤见[发布说明](docs/publishing.md)。
