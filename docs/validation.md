# 验证范围

公开仓库的检查只使用源码和合成数据，不读取本人或部署者的凭据，不请求 B站、小黑盒接口，不签到、不分享、不投币，也不安装驱动、创建调度或修改代理。

```powershell
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Test-Publish.ps1
```

该入口解析全部 PowerShell 语法，并运行 Python 标准库测试。测试覆盖源码语法、JSON 语法、公开目录白名单、敏感文件名、个人绝对路径、凭据字面量、二进制和缓存资源。Git 仓库还检查当前索引及所有分支/标签可达提交中的文件，避免删除工作区敏感文件后仍把历史推送出去。检测报告只输出文件路径及规则名称，不输出疑似凭据的内容。

白名单之外的源目录需先审查，再在 `tests/test_public_bundle.py` 中添加。不能通过移动私有资源、修改扩展名或削弱规则让检查通过。源码的二进制常量、合法协议字段名、占位符与合成测试值不等于私人账号数据；正则扫描也不能证明绝无敏感信息，发布者仍应审阅实际 Git 差异。

## 验收证据的含义

- 离线检查通过：当前公开源文件能解析，已覆盖的发布边界和合成行为检查通过。
- 依赖安装、签名模块构建通过：只证明相应工具链和构建成功。
- 部署者的真实验收：须由部署者使用自己的兼容 App、设备、凭据和本机资源，实际验证平台当天完成状态。不能用其他人的成功记录、退出码 0 或离线测试代替。

小黑盒的 APK、原生库、初始化缓存、设备会话和生成的 JAR 不随公开源码分发。上游原生签名适配源码没有在本仓库重新授权或复制。每位部署者需确认上游当前授权及其本人资源的使用权限。App、接口和设备兼容性可能变化，不能声称克隆后在任意电脑即可直接签到。

CI 只执行同样的离线检查；不配置账号 Secrets、不设置每日工作流、不接入第三方签名/通知服务，不在 GitHub Actions 上运行日常任务。
